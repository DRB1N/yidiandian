# 最短路径学习法理论依据

## 核心理论

### 1. 直接练习原则（Ultralearning）
出自 Scott Young 的《Ultralearning》。

**核心思想**：直接练习最终目标技能，而非先学一堆"前置知识"。学弹一首歌就直接练那首歌需要的和弦，而不是先学完一本乐理教材。

**应用规则**：
- 作品型目标：直接拆解作品所需技能，不做系统性前置课程
- 体系型目标：仍优先实践，理论作为辅助而非前置

### 2. 知识最小化（Knowledge Minimum）
**核心思想**：只学习达成目标所必需的最小知识集。多余的知识虽然有用，但会拖延目标达成时间。

**应用规则**：
- 每个技能单元问"不学这个能不能达成目标？"
- 如果答案是"能"，就不列入学习路径
- 区分"nice to know"和"must know"，只推荐 must know

### 3. 技能迁移与组件分析
**核心思想**：复杂技能 = 多个简单技能组件的组合。将大目标拆为可独立练习的小组件，逐个攻克后整合。

**应用规则**：
- 将目标分解为可独立检测的技能单元
- 每个单元有明确的"过关标准"
- 最后设置整合步骤，将各单元串联

### 4. 作品导向学习（Project-based Learning）
**核心思想**：以完成一个具体作品/项目为驱动，而非以"学会某门学问"为驱动。作品完成即目标达成。

**应用规则**：
- 目标必须是具体的、可验证的成果（如"弹完《Toxic》"而非"学会尤克里里"）
- 学习路径以作品完成为终点
- 不追求"全面掌握"，追求"能做出来"

## 决策分支

```
目标类型判断：
├── 作品型（弹一首歌、做一个项目、写一个脚本）→ 最短路径模式
│   └── 只拆解作品所需技能，禁止系统性扩展
└── 体系型（学会Python、掌握英语口语、入门摄影）→ 结构化但克制模式
    └── 适当分阶段，但每阶段仍以实践为主，不做大纲式堆砌
```

## 过关标准设计

每个技能单元必须设计清晰的过关标准：
- **可观测**：能用外部标准判断（如"能连续弹奏3遍不卡壳"）
- **具体**：不是"学会"而是"能做出X"
- **最小化**：刚好够用即可，不追求完美

示例：
- 技能单元：C-Am-F-G和弦转换
- 过关标准：能在60BPM下无卡顿完成4个和弦的循环转换，连续3轮
